01

Vision & Core Problem

Most people have goals but no structured bridge between the big picture and what to do today. Google gives 15 tabs. YouTube gives 3-hour videos. ChatGPT gives a wall of text. None of them give a visual, trackable, adaptive journey.

StepsBuilder is a Personal Goal Operating System — not a todo app, not a roadmap generator, not a journal. It's the layer that sits between your ambitions and your daily life and connects them intelligently.

Pain Point 1 — Macro

Learning roadmaps are either too vague or scattered across 10 different sources. No single visual, structured, at-a-glance journey.

Pain Point 2 — Micro

Even with a roadmap, you wake up and ask "what do I actually do today?" Gap between big picture and today's action.

03

Feature Areas

1 — Goal Management

Multiple goals simultaneously. Each goal has a type (career, fitness, business, learning, personal), a deadline or timeframe, and a status (active / paused / completed). Free plan: 3 goals max. Pro: unlimited.

2 — AI Roadmap Generation

User describes goal in plain language. Gemini returns structured JSON. Frontend maps JSON into prebuilt React Flow components. AI selects visual type based on goal type. Roadmap is not static — it evolves with user progress.

Flowchart → Learning/Skill goals Timeline → Deadline-driven goals Kanban → Project-style goals

3 — Daily Task Layer

AI looks at all active goals and current roadmap positions. Suggests a prioritized task list for today. Tasks tagged to which goal and which roadmap step. User can accept, modify, or ignore. Manual tasks ask "which goal does this relate to?" — maintaining connection.

4 — Daily Reflection (Journal)

User writes freely what they did. AI maps activities to goals and roadmap steps. Roadmap updates based on interpretation. User can confirm or correct AI's reading — this feedback loop keeps data accurate and improves prompt quality over time.

5 — AI Adaptation Engine

The heartbeat of the product. Watches pace over time. Stuck on a step too long → suggests breaking it down. Moving fast → accelerates roadmap. Consistently skipping certain tasks → notices and asks why. Everything else feeds data into this engine.

6 — Progress & Insights

Visual progress on each goal's roadmap. Streak tracking per goal. Momentum score (accelerating or slowing down). Weekly AI summary — what you actually did vs what was planned.

05

Data Models

User
├── name, email, password (bcrypt)
├── plan: 'free' | 'pro'
├── razorpaySubscriptionId
└── checkInPreference: 'morning' | 'evening'

Goal
├── userId (ref: User)
├── title, category, timeframe, deadline
├── status: 'active' | 'paused' | 'completed'
└── momentumScore: Number (AI updated)

Roadmap (one per Goal)
├── goalId (ref: Goal)
├── visualType: 'flowchart' | 'timeline' | 'kanban'
└── phases: [{ title, steps: [{ title, description, status, estimatedDays }] }]

Task
├── userId (ref: User)
├── goalId (ref: Goal)        ← goal connection
├── stepId (ref: Step)        ← roadmap connection
├── title, priority: 'high'|'medium'|'low'
├── dueDate, status: 'pending'|'completed'|'skipped'
└── isAiGenerated: Boolean

JournalEntry
├── userId (ref: User)
├── date, rawText (user's free-form input)
└── aiInterpretation: {
      goalMappings: [{ goalId, stepId, progressPercent }],
      untrackedActivities: [],
      productivityLevel: 'low'|'medium'|'high'
    }

Nudge (AI generated only, never user created)
├── userId, goalId
├── type: 'warning' | 'suggestion' | 'encouragement'
├── message, isRead, isDismissed
└── optionalStepBreakdown: []

Key design decision: JournalEntry is the only entity where raw user input gets transformed by AI into structured data. AI interpretation happens in one place — cleaner to build, easier to debug, easier to explain.

AI Prompt Structure — 5 Moments

Three rules apply to all prompts: (1) Always return pure JSON only. (2) Always define the exact JSON structure in the prompt. (3) Always include explicit constraints.

Moment 1 — Roadmap Generation

Input to Gemini
Goal: "{userGoal}" | Category: {category} | Timeframe: {timeframe}
Context: "{userContext}" | Hours/day available: {hours}

Return pure JSON only. No markdown. Structure:
{ visualType: 'flowchart'|'timeline'|'kanban', reason: string,
  phases: [{ title, steps: [{ title, description, estimatedDays }] }] }

Pick visualType: flowchart=learning/skill, timeline=deadline-driven, kanban=project-style.
Max 5 phases, 6 steps each. Total must fit within timeframe.

Moment 2 — Daily Task Generation

Input to Gemini
Active goals: {goalTitles + currentStep per goal}
Hours available today: {hours} | Day: {dayOfWeek}
Yesterday's completed tasks: {array} | Momentum scores: {perGoal}

Return 3-5 tasks max. Each: { title, goalId, stepId, priority, estimatedMinutes }
Prioritize goals with lower momentum. Fit within available hours.
Do NOT generate more tasks than user can realistically complete. An achievable list beats a complete list.

Moment 3 — Journal Interpretation

Input to Gemini
Journal entry: "{rawUserText}"
Active goals: {array with titles and current steps}

Return: { goalMappings: [{ goalId, stepId, progressPercent, activitiesMapped }],
  untrackedActivities: [], productivityLevel: 'low'|'medium'|'high' }

Be conservative with progress percentages. A single day rarely moves a step more than 10-15%.
Overestimating progress destroys long-term motivation.

Moment 4 — Adaptation / Nudge Generation

Input to Gemini
Goal: "{title}" | Current step: "{stepTitle}"
Days on this step: {n} | Estimated days: {estimated}
This week's journal entries: {array} | Momentum score: {score} (trend: {up|down})
Last nudge sent: {daysAgo} days ago

Return: { shouldNudge: boolean, type: 'warning'|'suggestion'|'encouragement',
  message: string (max 2 sentences), suggestBreakdown: boolean,
  newSteps: [] }

Do not nudge if last nudge was under 3 days ago. Sound like a supportive friend, not a productivity app.

Moment 5 — Weekly Insights

Input to Gemini
Week's completed tasks per goal: {array}
Journal entries this week: {array}
Momentum start vs end: {perGoal} | Goals with zero activity: {array}

Return: { summary: string (3-4 sentences max),
  perGoal: [{ goalId, status: 'on-track'|'needs-attention'|'great-progress' }],
  nextWeekSuggestion: string }

Monetization

Build Razorpay integration at the end, after core product is complete. Design the User model with a plan field from day one so adding payments is a clean addition, not a retrofit.

Free Tier

3 goals max. Basic AI task suggestions. Basic journal. Basic roadmap. Core loop fully functional.

Pro Tier

Unlimited goals. Full AI adaptation engine. Detailed weekly insights. Roadmap customization. Priority task intelligence.

The AI intelligence layer is what's monetized — not just a goal count limit. This is a deliberate product decision: free gets the structure, pro gets the brain.

10

Interview Talking Points

On Architecture

"I separated content generation from presentation. Gemini returns structured JSON and the frontend maps it into prebuilt React Flow components. Keeps AI costs low, rendering fast, and UI consistent."

On the Task-Roadmap Connection

"The roadmap and daily tasks aren't separate features — completing daily tasks is literally how you move through the roadmap. And the AI watches your pace and nudges you if you're stuck."

On Prompt Engineering

"I spent significant time prompt engineering to get consistent, structured, intelligent responses. Every prompt has explicit constraints — things like 'don't estimate more than 15% progress per day' — because the constraints are what make AI feel calibrated, not random."

On Monetization

"I designed the free and pro tiers around the AI features intentionally. Basic structure is free, but the intelligence layer is monetized. That came from thinking about where the actual value lives in the product."

On Performance

"I used Redis to cache AI-generated roadmaps so repeated views don't make redundant API calls — keeps the app fast and stays within free tier limits."
